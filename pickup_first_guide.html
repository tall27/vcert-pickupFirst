VCert Playbook Feature

How to Use pickupFirst

Automated Shared-Certificate Distribution for Clustered Endpoints & Follower Nodes

1. The Problem: "One Cert, Many Endpoints"

In modern enterprise architectures, multiple hosts often share the exact same TLS certificate (e.g., wildcards like *.example.com or multi-SAN certificates distributed across Nginx, Apache, F5 load balancers, and ingress controllers).

Normally, running a playbook on multiple servers causes every server to trigger a separate enrollment, creating different private keys and duplicate certificates.

The pickupFirst Solution:
Setting pickupFirst: true enables self-healing convergence: follower nodes query the trust platform (NGTS or TPP) for the latest certificate and server-side generated private key first, install it locally, and skip enrollment.

2. The 4-Way Decision Engine

On every playbook run, VCert executes the following deterministic decision flow:

Platform State Condition VCert Action
MATCH Installed thumbprint matches platform cert Defers to standard renewBefore window check. If outside the renewal threshold, exits with "certificate in good health. No actions needed" in <1 second.
PLATFORM NEWER Platform has a newer cert (or nothing installed yet) Downloads cert + server-side private key (via DEK decryption) + chain, installs locally, executes afterInstallAction, and skips enrollment.
REFUSE DOWNGRADE Platform certificate has an older expiration date than installed Safely logs a warning, refuses to overwrite files with an older cert, and exits cleanly.
NOT FOUND No certificate exists for this CN or ID Falls through to standard enrollment flow to create the certificate for the first time.

3. Playbook YAML Configuration

Add pickupFirst: true and set csr: service under your task's request section: 

certificateTasks:
  - name: shared-service-cert
    renewBefore: 1d                        # Auto-renew when <= 1 day remaining
    request:
      csr: service                         # Key generated server-side for shared pickup
      pickupFirst: true                    # ← Enables pickup-first mode
      pickupId: ''                         # Optional: override DN (TPP) or UUID/Thumbprint (NGTS)
      zone: 'Private 5 days'               # Target zone / issuing template
      subject:
        commonName: 'shared.example.com'   # CN to locate on platform
    installations:
      - format: PEM
        file: /etc/ssl/certs/app.crt
        keyFile: /etc/ssl/private/app.key
        chainFile: /etc/ssl/certs/chain.crt
        afterInstallAction: "systemctl reload nginx"
Field Type Default Description
pickupFirst boolean false Enables pickup-first convergence on supported platforms (ngts and tpp).
pickupId string (auto) Optional explicit identifier. For TPP: DN (e.g. \VED\Policy\...\cert). For NGTS: Certificate ID (UUID), Request ID, or Fingerprint. Defaults to discovering the latest cert by CN.

4. Cluster Deployment Workflow

Node 1: Leader Host

Runs the playbook first:

  1. Queries platform (finds nothing).
  2. Enrolls new certificate with csr: service.
  3. Platform generates private key and signs certificate.
  4. Node 1 installs cert + decrypted key.

Node 2..N: Follower Hosts

Runs identical playbook:

  1. Queries platform for commonName.
  2. Locates existing cert enrolled by Node 1.
  3. Retrieves cert + server-side key in ~2 seconds.
  4. Installs identical cert + key without enrolling.

Daily Cron / Scheduled Task

Runs on all nodes daily:

  1. Checks installed SHA-1 thumbprint vs platform.
  2. Matches → checks renewBefore.
  3. Exits immediately if within validity window (<1s).
  4. Zero unnecessary platform API load.

5. Running the Playbook via CLI

Execute your playbook using vcert run:

# Standard run
vcert run -f playbook.yaml

# Run with verbose debug logging (inspect locator & comparison)
vcert run -f playbook.yaml --debug

# Force renewal (bypasses pickupFirst to deliberately re-enroll)
vcert run -f playbook.yaml --force-renew
